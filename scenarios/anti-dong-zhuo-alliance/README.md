# 反董卓联盟

反董卓联盟剧本归属参考，位于 `scenarios/anti-dong-zhuo-alliance/`。

采用**190年1月游戏开局**，参考《三国志14》主要势力及《三国志》《后汉书》史载人物，偏向增加玩家选择。这是190年前后格局与现有地图的设计映射，不是严格190年一月史实复原。

## 当前规模

- 可玩势力：**40**；其中原游戏玩家资料表可核对21个主要势力，新增15个史载人物势力、4个部众/特殊势力。
- 地图记录：**148**块全部列出，其中126块建议归具名可玩势力，22块为地方官府/待考区域。
- 地方官府不是空城，不为增加数量而编造太守、把晚年割据提前或复活已死首领。青州黄巾保留可玩集团，但具名首领待定。
- 不修改地图原有 id、name、capital、state、wei/wu/shu、坐标或边界。此处单独记录剧本 owner_faction_id。

## 审核顺序

1. 先读《势力与城池归属.md》势力总表，再看按州逐城表。
2. 查看《史料与取舍.md》中曹操谯城、刘备平原、刘表前移、张鲁提前独立、马腾韩遂拆分等取舍。
3. 接入时按城池ID关联；保留表中注明的推定、时代映射与游戏化取舍。

## 文件

- `scenario.json`：唯一机器数据源；包含剧本年月、势力表、148条地块归属、来源及解释。
- `势力与城池归属.md`：由JSON同一批记录生成的人工审核表。
- `史料与取舍.md`：来源、映射限制、重点取舍与扩展候选。
- `势力色表.md`：40个势力的HEX与RGB、原色所属及同名/借色说明。
- `verify.cjs`：仅用Node标准库的校验脚本。
- `verification.json`：数据核验结果。

## 接入方法

按 `city_ownership[].city_id` 与地图 `provinces[].id` 对接。归属使用 `owner_faction_id`；不要用名称或现有地图的 `wei/wu/shu` 做剧本归属。

JSON没有重复存放 polygon，也没有给262年的 capital 字段冒充190年郡治。势力的 start_city_id 是**游戏开局支点**，不是历史州治、实际军营或严格郡治。

`owner_faction_id: null` 与 `basis: local_administration` 表示暂未核定具名势力；加载方应保留地方官府状态，不能视为空城。青州黄巾的 `leader: null` 表示集团首领待定，角色系统接入前需选历史候选或明确设为自创人物。

## 运行校验

放入仓库后：

`node scenarios/anti-dong-zhuo-alliance/verify.cjs`

也可传入独立地图文件路径：

`node verify.cjs /absolute/path/to/gpkg_all_data.json`

校验148个ID一一对应、名称一致、40势力都有开局领地、首城归属、来源引用、联盟成员、null语义与地图摘要；不会改写地图。资源、兵力、武将全集、平衡数值和战役事件留待后续游戏系统设计。
